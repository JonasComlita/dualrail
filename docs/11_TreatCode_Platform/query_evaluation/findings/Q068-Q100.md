## Retrieval risks

- **Filename collisions:** `semantic` queries for `ternary_redo_wal.h`, `kernel/vfs.trit`, `APP_MANIFEST.json`, `IMAGE_FORMAT_MANIFEST.json`, `coverage_matrix.json`, and `App.tsx` return a component, source record, and many symbols. The top-ten gate must retain the expected component/source ID and provenance path rather than accepting any similarly named symbol.
- **Short symbol names:** `symbol` mode is safest for `bio_get`, `bio_wal_append`, `net_socket_create`, `os_fb_init`, and `desktop_launch_hotkey`; broad terms such as `buffer`, `host`, or `app` have many low-value matches and can displace the authoritative implementation.
- **Exact-ID safeguards:** Q070, Q073, Q075, Q087, Q090, Q094, Q095, Q096, Q097, Q098, and Q100 deliberately use `exact` mode because status/decision/test/run records are easy to confuse with similarly named source or documentation records.
- **Cross-layer provenance:** Q070, Q073, Q078, Q087, Q096, and Q099 require more than one source path. A result is not sufficient unless its provenance includes at least one expected path and the answer opens all expected paths before asserting a cross-layer fact.
- **Optional/negative wording:** Q078, Q090, Q091, Q094, Q095, Q098, and Q099 ask whether a capability is implemented, missing, scaffolded, or optional. Retrieval should not treat a capability name, contract title, or benchmark label as evidence of completion.
- **Generated snapshot freshness:** The snapshot and run records carry commit/time provenance. Re-running the corpus after registry or source edits is required; otherwise a correct query can appear stale or a stale status can look current.
